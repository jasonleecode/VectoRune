# 目录与架构改造记录

日期：2026-11-09。依据：[设计审视](design-review-2026-11-09.md)。目标 ARM 设备暂未确定。

本轮先调整目录，再完成可在 Mac 验证的核心接口、资源复用和构建安装改造。以下分别列出已完成内容和仍未完成的设计目标。

## 目录职责

| 目录 | 当前职责 |
| --- | --- |
| `core/` | `MapBackend` 会话接口、`MapRegistry` 注册表、`MapDocument` 调度、缓存、地点索引、路由服务及 GPX |
| `plugins/garmin/` | Garmin 格式适配、NET/NOD/属性解析接入、兼容头、地图样式和字形 |
| `plugins/mbtiles/` | MBTiles 适配、MVT 名称索引程序和默认样式 |
| `mapviewer/` | Qt Quick 界面、定位和导航交互、MapLibre 接入 |
| `lib/` | 原有第三方解析库，保留许可证 |
| `tools/` | 导入、检查、路由命令行程序、OSM 转换入口和 tilemaker 子模块 |
| `tests/` | 核心、格式、Garmin、集成和 QML 界面测试 |
| `experiments/` | 从根目录迁入的 navit、navitdrv、Web 和历史脚本，内容保留，不参与主构建 |

`scripts/osm_2_mbtile.sh` 仅保留兼容包装，实际转换入口在 `tools/convert_osm.py`。

## 已实现

### P1：格式会话和生命周期

- `MapDocument` 不再按 IMG/MBTiles 分支实现解析、搜索和路线计算；由注册表创建独立格式会话。
- 新格式通过 `plugins/builtin.cpp` 注册；可在构建时关闭现有格式。当前是静态注册，没有动态加载第三方二进制插件。
- 返回地图能力：瓦片、几何、名称搜索、附近地点、路由和条件路由。栅格地图不启用地名搜索；缺少可用路网或限制未解码时不启用路由。
- 加载成功才替换当前会话；失败保留旧地图。旧会话结果不会混入新地图。
- 渲染对象持有会话租约，直到自身销毁。旧样式和缓存不会过早删除，也不再保留所有历史地图直到退出。
- 切图后清理旧 QML provider 和参数对象，退出/取消时停止辅助进程。

这建立了格式插件的第一层边界。当前显示交付仍以 MapLibre 样式 URL 为主，尚没有通用的“按区域/层级查询几何”接口或其他渲染后端实现。

### P1：导入复用和缓存管理

- IMG 按文件内容 SHA-256 和导入格式版本建立持久缓存，重新打开同一地图可直接复用。
- 导入完成后原子发布 manifest；缺失或截断文件不会当作完整缓存使用。
- 使用文件锁和会话租约，清理时跳过正在导入或显示的地图；失败导入会清理未完成文件。
- Garmin 导入缓存预算为 512 MiB。单份结果超过预算会拒绝载入；多份被渲染器占用的结果允许暂时超过总预算，解除占用后继续淘汰最久未用的结果。
- MBTiles 名称索引使用独立的 128 MiB 缓存预算。以上是缓存磁盘预算，不是进程内存或整机资源上限；MapLibre 自身还有缓存。

### P1：路由服务复用

- 将图构建和单次路线查询分开；道路图和转向限制自动机在同一出行模式下复用。
- 持久辅助进程使用逐行 JSON 请求/响应；路线参数异常、未知限制仍显式拒绝。
- 切换驾车/骑行/步行时只保留一个模式图，先释放旧图再构建新图；空闲 60 秒后退出以归还内存。
- 运行时使用带版本标记的 `routing.cbor`，避免每次规划都解析文本 JSON；命令行默认仍输出 JSON 供独立检查，`--compact` 只输出运行所需数据。

CBOR 是紧凑序列化数据，不是内存映射图索引。进程首次启动仍完整加载路网并建图，这部分低内存改造尚未完成。

### P1：统一构建和安装入口

- 根目录 CMake 可分别构建核心、格式适配、辅助程序、界面和测试。
- 不构建界面时不需要 QMapLibre/Qt Quick/Qt Location；格式适配可以单独关闭。
- 安装规则覆盖应用和辅助程序，修复原先仅安装主程序的缺口。
- 数据目录可配置，不再编译进当前机器的源码路径；没有默认地图也能启动并通过菜单加载。
- 提供 ARM64 Linux 工具链模板，要求显式指定目标 sysroot，详见 [平台说明](platforms.md)。

Qt/QMapLibre 依赖的完整发行包、真实 Linux/ARM 部署还未验收。

### P2：名称和空间索引

- Garmin 导入时生成 SQLite 地点库；主程序不再完整加载 `pois.json`。
- MBTiles 首次搜索建立持久索引，后续查询不再反复解压全部最高层级瓦片。首次建立索引仍需要全量扫描。
- 名称使用 Unicode 归一化、二元字符倒排索引和完整名称索引；附近地点使用 R-tree 筛选，再按地理距离精确比较。
- 单字符包含查询仍扫描索引中的名称行，不解压地图或加载完整 POI 对象。
- 全部候选排序后才限制 50 条，修复后出现的精确匹配被前 50 条结果挡住的问题。
- 保留源语言搜索；没有添加中文到拼音转换或在线地名服务。

### P2：转换入口与验证组织

- `tools/convert_osm.py` 接受明确输入、输出和配置参数，不依赖调用目录；已有输出不会被覆盖。
- 转换使用临时结果，经 SQLite 和瓦片检查后发布；失败不留下半成品输出。
- 缺少默认配置的外部海岸线/地表 shapefile 时，明确提示并使用 OSM 数据；自定义配置或显式辅助数据目录缺失则报错，不自动下载。
- 转换包装已用独立替身程序测试参数、错误和结果发布。本机尚无已构建的 tilemaker，因此本轮未宣称完成真实 PBF 转换验收。
- 增加核心生命周期、缓存、索引、插件能力、路由服务协议和转换入口测试。
- 新增 macOS 核心 CI 工作流；本地验证已执行，远端 CI 尚未运行。

## 本机观察

条件：Mac ARM64、Qt 6.10.1、根目录 Release 构建。单次观察，不是目标板预算或统计分位数。

| 项目 | 结果 |
| --- | ---: |
| 北京 IMG：地理对象数 | 284,231，回归一致 |
| 路网/转向限制 | 92,479 条道路，602 条限制，回归一致 |
| 运行时 `routing.cbor` | 25.42 MiB |
| 原 JSON 路网 | 43.69 MiB |
| Garmin `places.sqlite` | 27.84 MiB，包含名称与空间索引 |
| 仍使用的 `map.geojson` | 126.43 MiB |
| 新导入（包含地点索引） | 约 6.00 秒，峰值 RSS 421 MiB |
| 同一服务第一次规划 | 约 0.86 秒，包含读文件与构图 |
| 同一服务第二/第三次规划 | 约 9.3 / 8.9 毫秒，图构建次数仍为 1 |
| 上述三次路线长度 | 均为 4,339.36 米 |
| MBTiles 缓存命中搜索“天安门” | 约 0.20 秒，12 条，首条精确匹配 |

导入时间比旧审视数字包含了新的索引构建工作，构建优化级别也不同，不能直接当作严格前后性能对比。新的导入峰值仍较大，尚未达到低资源 ARM 验收目标。

## 下一批仍按优先级推进

1. **P1：几何分块与按需查询。** 目前 IMG 仍一次性展开为完整 GeoJSON，应先实现可预生成的空间/层级索引及按视区读取，减少低缩放级别的加载和渲染压力。
2. **P1：真正的紧凑路网索引。** 将预处理结果直接保存为可复用图结构，评估文件映射、空间分区和候选道路索引，减少首次规划与进程常驻内存。
3. **P1：目标 SDK 部署与资源预算。** 硬件确定后完成依赖打包、Linux/ARM 运行与预算验收。
4. **P2：补齐转换链路。** 构建并验收真实 tilemaker 转换，再接入 OSM PBF → Garmin IMG。
5. **P2：导航完整性。** 道路投影匹配、速度来源、真实轨迹回放，以及有独立样本支持的时段条件解码；现阶段仍不声明完整导航。
6. **P2：持续性能回归。** 将首次/缓存命中和多地图场景纳入基准，用目标设备预算建立门槛。

TYP 自定义样式、通用 Garmin 条件时段规则及目标板性能承诺，均未因本次目录与架构改造而变为已支持能力。
